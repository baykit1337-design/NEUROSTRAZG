# MVLEMPYR downloader

Качалка глав книг в отдельные `.txt`-файлы. Веб-интерфейс + CLI.
Только HTTP-запросы, без браузерной автоматизации.

## Установка

```bash
pip install -r requirements.txt
```

Python 3.10+.

## Веб-интерфейс

```bash
python webapp/app.py
```

Откроется `http://127.0.0.1:8765`. Дальше три шага:

1. **Найти книгу** — вставьте ссылку, слаг (`insect-tamers-ascension`) или
   числовой код (`6615`).
2. **Выбрать, где создать папку** — обзор папок прямо в интерфейсе, плюс поле
   с именем папки (подставляется название книги, можно переписать). Внизу
   показывается итоговый путь и оценка времени.
3. **Скачать** — прогресс-бар, счётчики, кнопка «Остановить». Рядом кнопка
   «Ссылки» для запасного плана (см. ниже).

Сервер слушает только `127.0.0.1`: он даёт доступ к файловой системе для
выбора папки, поэтому наружу его выставлять не нужно.

## CLI

```bash
# по ссылке, папка рядом со скриптом
python cli.py https://www.mvlempyr.io/novel/insect-tamers-ascension

# по коду, свой путь и имя папки
python cli.py 6615 --out ~/Books --name "Insect Tamer"

# кусок книги
python cli.py insect-tamers-ascension --from 100 --to 200

# найти книгу в каталоге
python cli.py --search "insect tamer"

# проверить целостность уже скачанной папки
python cli.py --verify ~/Books/"Insect Tamer"

# запасной план: список ссылок для WebToEpub
python cli.py 6615 --links links.txt
```

## Что получается на выходе

```
~/Books/Insect Tamer/
├── 0001 - Chapter 1_ Awakening.txt
├── 0002 - Chapter 2_ First Contract.txt
├── …
├── state.json     ← что уже скачано (нужен для докачки)
└── errors.log     ← главы, которые не удалось получить, и причина
```

Номер главы дополняется нулями до 4 знаков, иначе ломается сортировка по
имени. Из названия главы вычищаются символы, недопустимые в именах файлов.
В начале каждого файла — название книги и название главы.

## Докачка

Прогресс лежит в `state.json` в папке книги. Скрипт можно прервать в любой
момент (Ctrl+C или «Остановить») и запустить снова — готовые главы
пропускаются, работа продолжается с места остановки. Если файл главы удалить
вручную, при следующем запуске он скачается заново.

## Как это работает

Сайт состоит из двух частей, и мы используем обе — каждую для своего:

| Хост | Что берём |
|---|---|
| `chap.heliosarchive.online` | каталог и оглавление (открытый REST API) |
| `www.mvlempyr.io` | текст глав (единственный доступный источник) |

| Шаг | Запрос |
|---|---|
| Резолв книги | `GET /wp-json/wp/v2/mvl-novels?slug=insect-tamers-ascension` |
| Оглавление | `GET /wp-json/wp/v2/posts?slug[]={code}-1&slug[]={code}-2&…` |
| Текст главы | `GET https://www.mvlempyr.io/chapter/{code}-{n}` |

**На эндпоинте `mvl-novels` нельзя использовать `_fields`.** Кастомные поля
(`novel-code`, `total-chapters`, `name`, `slug`) не зарегистрированы в схеме
WP REST, и `_fields` их молча выбрасывает: ответ приходит как `[[]]` — массив
пустых объектов. Это не «книга не найдена», а испорченный запрос, и программа
сообщает об этом отдельным понятным сообщением, а не «ничего не нашлось».

Код книги из ссылки на главу берётся регуляркой `/chapter/(\d+)-\d+`, без
сетевого запроса.

Текст главы через REST получить нельзя: в выдаче поста есть только `id`,
`date`, `link` и `acf`, полей `title` и `content` нет. Страницы `/chapter/*`
на бэкенд-хосте закрыты правилом WAF. Поэтому текст берётся со страниц
витрины: `div#chapter → p`. Название главы при этом приходит готовым из API
(`acf.ch_name`), из разметки его доставать не нужно.

Абзацы соединяются через пустую строку, абзацы из одних `*` (разделители
сцен) сохраняются, блоки с обфусцированными классами (`ke400008d2`,
`rb9bdb230d`) — это реклама, они выбрасываются. На динамический `span` внутри
`#chapter` парсер не завязывается: его id меняется от главы к главе.

## Нагрузка на сервер

Витрина стоит за Cloudflare, поэтому доступ к ней намеренно медленный:

- **один поток**, не пять;
- пауза **2–4 секунды** между главами со случайным джиттером;
- одна `Session` на весь прогон — кука доступа переиспользуется;
- запросы идут через `curl_cffi` с отпечатком Chrome и заголовками браузера
  (`Accept`, `Accept-Language`, `Referer`, `Sec-Fetch-*`);
- **при 403 или 429 прогон останавливается совсем**, без ретраев: повторы по
  блокировке только усугубят ситуацию. В `errors.log` пишется, на какой главе
  встали, чтобы можно было продолжить позже;
- если вместо главы пришла заглушка Cloudflare, она не сохраняется как текст —
  прогон останавливается.

К REST API (каталог и оглавление) блокировок нет: там пачки по 100 слагов и
пауза 1–2 секунды, 5xx ретраится с экспоненциальным backoff.

541 глава при паузе 3 секунды — примерно 30–40 минут фоном, один раз.

Никаких headless-браузеров, ротации прокси и разгадывания капчи.

## Проба перед прогоном

Прежде чем качать книгу целиком, стоит проверить одну главу:

```bash
python probe.py            # глава 6615-200
python probe.py 6615-1
```

Скрипт делает **ровно один** запрос и печатает статус, размер ответа, найден
ли `div#chapter`, число абзацев и начало текста.

- **Исход A** — пришёл HTML с `div#chapter`: путь рабочий, можно качать.
- **Исход B** — заглушка Cloudflare: обходить её не пытаемся, переходим к
  запасному плану.

## Запасной план (если исход B)

Если витрина не пускает обычные HTTP-запросы, текст берётся расширением
**WebToEpub** в браузере: оно работает внутри реальной сессии, поэтому вопрос
Cloudflare не возникает вообще. Оглавление при этом всё равно берётся из API —
оно не заблокировано, — так что список ссылок генерируется скриптом:

```bash
python cli.py 6615 --links links.txt
```

В веб-интерфейсе то же самое делает кнопка «Ссылки» рядом с «Скачать».
Если mvlempyr не поддерживается расширением из коробки, парсер для него
пишется на селекторах из раздела выше.

## Отчёт о целостности

После скачивания выводится сводка: сколько скачано, сколько пропущено (уже
было), сколько ошибок. Отдельно отмечаются дыры в нумерации — номера, которых
нет в каталоге сайта. `--verify` сверяет `state.json` с реально лежащими
файлами и показывает, каких глав не хватает.

Сверка по цепочке `prev`/`next` со страниц глав намеренно не делается: она
удваивает трафик, а список отсутствующих номеров даёт тот же результат из
оглавления.

## Тесты

```bash
python -m unittest tests.test_mvl -v
```

79 тестов. Сетевые тесты гоняются против локального мок-сервера, который
играет обе роли сразу: на `/wp-json/*` отвечает как REST API, на `/chapter/*` —
как витрина. Покрыты дыра в нумерации, глава с вечной 500-й, блокировка 403
посреди прогона, заглушка Cloudflare с кодом 200, докачка после блока,
однопоточность и то, что `_fields` не уходит на сервер. Живой сайт для тестов
не нужен.
