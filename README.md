# MVLEMPYR downloader

Качалка глав книг в отдельные `.txt`-файлы. Веб-интерфейс + CLI.
Только HTTP-запросы, без браузерной автоматизации.

## Установка

```bash
pip install -r requirements.txt
```

Python 3.10+.

## Веб-интерфейс

```bash
python webapp/app.py
```

Откроется `http://127.0.0.1:8765`. Дальше три шага:

1. **Найти книгу** — вставьте ссылку, слаг (`insect-tamers-ascension`) или
   числовой код (`6615`).
2. **Выбрать, где создать папку** — обзор папок прямо в интерфейсе, плюс поле
   с именем папки (подставляется название книги, можно переписать). Внизу
   показывается итоговый путь.
3. **Скачать** — прогресс-бар, счётчики, кнопка «Остановить».

Сервер слушает только `127.0.0.1`: он даёт доступ к файловой системе для
выбора папки, поэтому наружу его выставлять не нужно.

## CLI

```bash
# по ссылке, папка рядом со скриптом
python cli.py https://www.mvlempyr.io/novel/insect-tamers-ascension

# по коду, свой путь и имя папки
python cli.py 6615 --out ~/Books --name "Insect Tamer"

# кусок книги
python cli.py insect-tamers-ascension --from 100 --to 200

# найти книгу в каталоге
python cli.py --search "insect tamer"

# проверить целостность уже скачанной папки
python cli.py --verify ~/Books/"Insect Tamer"
```

## Что получается на выходе

```
~/Books/Insect Tamer/
├── 0001 - Chapter 1_ Awakening.txt
├── 0002 - Chapter 2_ First Contract.txt
├── …
├── state.json     ← что уже скачано (нужен для докачки)
└── errors.log     ← главы, которые не удалось получить, и причина
```

Номер главы дополняется нулями до 4 знаков, иначе ломается сортировка по
имени. Из названия главы вычищаются символы, недопустимые в именах файлов.
В начале каждого файла — название книги и название главы.

## Докачка

Прогресс лежит в `state.json` в папке книги. Скрипт можно прервать в любой
момент (Ctrl+C или «Остановить») и запустить снова — готовые главы
пропускаются, работа продолжается с места остановки. Если файл главы удалить
вручную, при следующем запуске он скачается заново.

## Как это работает

Сайт состоит из двух частей: витрина `www.mvlempyr.io` (Webflow за Cloudflare)
и контент `chap.heliosarchive.online` (WordPress, открытый REST API).
**Мы работаем только со вторым хостом**, витрину не трогаем вообще.

| Шаг | Запрос |
|---|---|
| Поиск книги | `GET /wp-json/wp/v2/mvl-novels?search=…&_fields=…` |
| Оглавление | `GET /wp-json/wp/v2/posts?slug[]={code}-1&slug[]={code}-2&…` |
| Текст главы | `GET /wp-json/wp/v2/posts/{id}?_fields=content,title` |
| Запасной путь | `GET /chapter/{code}-{n}` + разбор HTML |

Параметр `?slug=` на эндпоинте каталога не работает (внутренний WP-слаг не
совпадает с вебфлоу-слагом), поэтому поиск идёт через `?search=` со сверкой
слагифицированного названия. Поля всегда обрезаются через `_fields`, чтобы не
тянуть синопсисы.

Перед скачиванием программа проверяет на одной главе, отдаёт ли REST тело
текста. Если `content.rendered` непустой — текст берётся из JSON, HTML не
парсится вообще (самый дешёвый путь по трафику). Если пусто — разбирается
страница главы: `h2#chapter-name` для заголовка, `div#chapter → p` для текста.
Абзацы соединяются через пустую строку, абзацы из одних `*` (разделители сцен)
сохраняются, блоки с обфусцированными классами (`ke400008d2`, `rb9bdb230d`) —
это реклама, они выбрасываются. На динамический `span` внутри `#chapter`
парсер не завязывается: его id меняется от главы к главе.

## Нагрузка на сервер

Значения зашиты и подниматься не должны:

- не больше 5 одновременных соединений;
- пауза 1–2 секунды между пачками;
- при HTTP 429 или 5xx — экспоненциальный backoff, 3 попытки, потом глава
  пропускается с записью в `errors.log`;
- HTTP 404 не ретраится — главы просто нет.

Никаких headless-браузеров, ротации прокси и разгадывания капчи.

## Отчёт о целостности

После скачивания выводится сводка: сколько скачано, сколько пропущено (уже
было), сколько ошибок. Отдельно отмечаются дыры в нумерации — номера, которых
нет в каталоге сайта. `--verify` сверяет `state.json` с реально лежащими
файлами и показывает, каких глав не хватает.

Сверка по цепочке `prev`/`next` со страниц глав намеренно не делается: она
удваивает трафик, а список отсутствующих номеров даёт тот же результат из
оглавления.

## Тесты

```bash
python -m unittest tests.test_mvl -v
```

52 теста. Сетевые тесты гоняются против локального мок-сервера, который
повторяет формат ответов WP REST — включая дыру в нумерации, главу с вечной
500-й ошибкой и оба режима отдачи текста (JSON и HTML). Живой сайт для тестов
не нужен.
