# Как выпустить релиз

Порядок на семь шагов. Всё делается из папки проекта.

---

## 0. Где записана версия

В одном месте: `mvl/__init__.py`, строка `__version__`.

Оттуда её берут шапка интерфейса (через `/api/about`) и `cli.py
--version`. Больше нигде она не записана и записана быть не должна: две
записи однажды разойдутся, и вопрос «какая у меня версия» останется без
ответа.

Числа значат вот что:

| Меняется | Когда |
|---|---|
| первое (`2`.0.0) | сломался привычный порядок работы: пропала вкладка, переехали настройки, файлы стали называться иначе |
| второе (2.`1`.0) | появилось умение: источник, вкладка, рейтинг |
| третье (2.0.`1`) | что-то починено, нового не прибавилось |

---

## 1. Убедиться, что всё зелёное

```
python -m unittest discover -s tests -q
```

Должно кончиться словом `OK`. Если хоть один тест красный — релиза нет.
Не «поправлю потом»: выпущенная версия живёт у людей на дисках, и откатить
её нельзя.

## 2. Проверить руками то, что тесты не видят

Тесты офлайновые: сеть они не трогают. Перед выпуском стоит своими
руками скачать одну книгу с каждого источника, которым пользуетесь, и
снять по одному срезу каждого рейтинга. Пяти минут хватает, а ловится
ровно то, чего тест поймать не может.

## 3. Поднять версию

Открыть `mvl/__init__.py`, поменять `__version__`. Проверить:

```
python cli.py --version
```

## 4. Дописать историю

В `CHANGELOG.md` завести раздел новой версии и записать, что изменилось.
Писать для того, кто это будет читать через полгода: не «поправлен
разбор», а что именно вело себя не так и как теперь.

## 5. Закоммитить и поставить тег

```
git add -A
git commit -m "Версия 2.1.0"
git tag -a v2.1.0 -m "NEUROSTRAZH 2.1.0"
git push origin main
git push origin v2.1.0
```

Тег обязан совпадать с `__version__` с точностью до буквы `v` впереди.
Тег, поставленный не на тот коммит, снимается так:

```
git tag -d v2.1.0
git push origin :refs/tags/v2.1.0
```

## 6. Собрать архив

```
git archive --format=zip --prefix=neurostrazh-2.1.0/ -o neurostrazh-2.1.0.zip v2.1.0
```

`git archive` кладёт в архив **только то, что лежит в репозитории**.
Это и есть главная причина им пользоваться: ни `proxies.txt`, ни
`config.json`, ни папка `data/` в архив не попадут — они в `.gitignore`.
Собирать архив, заархивировав папку целиком, нельзя: туда уедут ваши
прокси с паролями и ключ от языковой модели.

Проверить, что уехало:

```
unzip -l neurostrazh-2.1.0.zip | grep -E "proxies|config.json|data/"
```

Ответ должен быть пустым.

## 7. Выложить

На GitHub: **Releases** → **Draft a new release** → выбрать тег
`v2.1.0` → заголовок `NEUROSTRAZH 2.1.0` → в тело скопировать раздел из
`CHANGELOG.md` → приложить собранный `.zip` → **Publish**.

---

## Что человек делает с релизом

Распаковывает архив и запускает:

- Windows — `Запустить.bat`
- macOS — `Запустить.command`
- иначе — `python start.py`

Зависимости `start.py` доставляет сам. Питон нужен свой, версии 3.11 или
новее.

Своих `proxies.txt` и `config.json` в архиве нет — это правильно. Рядом
лежит `proxies.example.txt`, с него и начинают.

## Что в релиз попадать не должно

**Две скачанные книги `.epub` убраны.** Чужой текст в публичном
репозитории — лишнее, к программе они отношения не имели и остались от
проверок. `*.epub`, `*.fb2` и `*.mobi` теперь в `.gitignore`, так что
следующая туда не попадёт сама.

Из истории коммитов они при этом **не исчезли**. Обе залиты одним
коммитом `7e8d97b`, пятым из девяноста восьми: убрать их оттуда значит
переписать всю историю после него и запушить с силой. Делать это стоит,
только если чужой текст в открытой истории действительно мешает —
тогда так:

```
git filter-repo --invert-paths \
  --path "Run_Away 294-388.epub" \
  --path "ГОТОВЫЙ_Insect_T..._201-365.epub"
git push --force-with-lease origin claude/practical-hopper-i6hsy1
```

Ветка сейчас основная у репозитория, поэтому такая перезапись задевает
всё, что от неё отходит.

**`БД для скачивания.zip`, 856 КБ.** Расширение
[dteviot/WebToEpub](https://github.com/dteviot/WebToEpub) (GPL-3.0),
положенное как справочник: из него взяты правила разбора для
сайтов-сливов и Webnovel — адреса, селекторы, кодировки. Работе
программы оно не нужно, но нужно тому, кто будет добавлять сайты:
там разобрана добрая сотня. Лицензия и авторские надписи внутри архива
не тронуты — переименован только сам файл.

Проверить размер того, что уедет:

```
git archive --format=zip v2.1.0 | wc -c
```

Без этого архива релиз занимает около четверти мегабайта.

---

## Если что-то пошло не так после выпуска

Выпускается исправление третьим числом: `2.1.0` → `2.1.1`. Тот же
порядок с первого шага. Удалять уже опубликованный релиз не нужно —
пусть остаётся: по нему видно, что было, и с чем сравнивать.
